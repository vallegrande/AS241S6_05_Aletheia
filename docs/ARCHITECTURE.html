Propuesta actual: certificados válidos — evidencias profesionales verificables (títulos, certificaciones, logros, portafolio).

Elemento Detalle

2) Historial de transacciones (BD propia) con filtrado por red conectada ✅

Se eligió almacenamiento en BD (frente a usar la API de un explorador de bloques): histórico completo propio, sin límites externos y filtrable por usuario.

Aspecto Detalle
Tablatransacciones (uid, evidencia_id, tx_hash, chain_id, created_at)
ReglasUna fila por transacción (re-certificaciones incluidas); UNIQUE (evidencia_id, tx_hash) evita duplicados
APIGET /api/transactions — historial del usuario, ordenado por fecha descendente
Filtro por red conectadaEl endpoint acepta ?chain_id=<red actual>; ej.: ZkSYS/Syscoin 57000·901, Sepolia 11155111, Hoodi 560048, Polygon Amoy 80002
UI (panel → Historial)Fecha, evidencia implicada, red, hash de tx copiable y enlace directo al explorador oficial de cada red

Los exploradores por red están mapeados en src/lib/web3/chains.ts (Ethereum/Sepolia/Hoodi, Syscoin/ZkSYS, Polygon, BNB, Arbitrum, Optimism, Base, Avalanche), de modo que “ver transacción” siempre abre el explorador correcto para la red en que ocurrió la transacción.
